# Checkout Test Fill / Checkout 测试资料填充（v1.2.11）

插件弹窗、网页按钮、提示及隐私说明默认根据 Chrome 界面语言显示英文、简体中文或繁体中文；其他语言默认英文。也可以在弹窗“界面语言”中手动选择，立即同步到网页按钮与隐私说明。扩展名称仍由 Chrome 按浏览器语言显示，不受弹窗内的选择影响。图标为结账小票加确认勾选。

运行 `python scripts/build_store_zip.py` 会生成两个内容完全相同的 ZIP：商店上传包与线下试用包。两者均仅对 JavaScript 做最小化，不混淆、不修改源码。线下试用时将 ZIP 解压后，在 `chrome://extensions` 使用“加载已解压的扩展程序”选择解压目录；商店安装的用户通过商店更新，线下加载的目录不会自动变成商店安装版。

旧版 CRX 的签名私钥保存在项目外的 `D:\AI\cktestfill-private\checkout-test-fill.pem`，不要上传或分享。开发时可直接加载本项目根目录，不会再因该私钥触发 Chrome 的密钥文件警告。

首次使用时，checkout 网页右侧中间显示简短的数据说明和“启用并生成”按钮；点击后才开始读取表单并立即填充。启用后，插件会在 URL 含 `checkout` 的页面识别邮箱、名、姓、国家四类字段并显示“生成资料”按钮。支持中英文字段名。即使页面默认香港、暂时没有 ZIP 字段，按钮也会出现。**只有点击按钮后才切到美国并填写**。如启用测试卡功能，也会填写识别到的卡片字段。插件不会提交订单或付款。

## 安装与使用

1. 在 Chrome 打开 `chrome://extensions`，开启“开发者模式”。
2. 点击“加载已解压的扩展程序”，选择本文件夹。若安装过旧版，点击该扩展的“重新加载”，然后刷新 checkout 页面。
3. 首次使用时在 checkout 网页右侧中间点击“启用并生成”；此后可在相同位置点击“生成资料”，填写新资料。再次点击会覆盖上一组。
4. 如需更改国家、州或测试卡配置，点击扩展图标，在“配置”里修改并保存。默认美国／加州；测试卡默认启用。

插件弹窗提供 [隐私说明](privacy.html) 和“清除本地数据”按钮；清除本地数据也会撤销首次启用，之后需再次启用。

多步骤 checkout 可分别在联系、收货、支付页面点击“生成资料”。联系页即使只有邮箱也会显示按钮；后续步骤沿用同一个标签页中首次生成的姓名、邮箱和地址。每次进入新步骤需点击按钮，插件不会自动进入下一步或提交订单。回到同一类步骤再次点击会生成新资料。当前步骤资料暂存在扩展的会话内存中，关闭标签页、重启浏览器或更新插件后会清除。

邮箱根据生成的姓名和 4 位年份组成，例如 `jessica.smith1992@gmail.com`，域名在 Gmail 和 Outlook 之间随机选择。插件会记录近期使用的邮箱以避免重复。**这些只是格式上像真实邮箱的测试数据，不能保证对应邮箱存在或可收信。** 如需接收订单邮件，请在表单里改成你控制的邮箱。

遇到“Confirm Email Address”“确认电子邮箱”等重复邮箱字段时，插件会将主邮箱框中的同一个地址再填一次；已有内容的确认框不会在自动补填时被覆盖。

页面同时有营销短信订阅电话和收货电话时，插件优先填写收货电话，不填写营销订阅电话。

## 国家、州和地址

配置中目前只有美国，州可以选择美国各州。内置的 10,000 条核实来源地址全部位于加州旧金山市。选择其他州时，插件会选择该州并填写姓名、邮箱、电话，但街道、城市、ZIP Code 留空，避免拼出错误地址。默认是美国／加州。

地址取自 [旧金山市 Enterprise Addressing System 开放数据](https://data.sfgov.org/Geographic-Locations-and-Boundaries/Addresses-with-Units-Enterprise-Addressing-System/ramy-di5m)，由 City and County of San Francisco 提供。OpenAddresses [源文件](https://github.com/openaddresses/openaddresses/blob/master/sources/us/ca/san_francisco.json) 将其标为 [PDDL 1.0](https://opendatacommons.org/licenses/pddl/1-0/)。脚本 `scripts/build_addresses.py` 可重新提取。数据包含来源记录中的完整门牌号、街道和 ZIP Code；每轮洗牌后逐条使用，不编造门牌号。地址记录真实存在于数据源中，但不保证目前仍可投递。

姓名由 [美国社保署 1990 年代常见名字](https://www.ssa.gov/oact/babynames/decades/names1990s.html)与[美国人口普查局 2010 年常见姓氏](https://www2.census.gov/topics/genealogy/2010surnames/Names_2010Census_Top1000.xlsx)组合，属于常见姓名组合，不冒用特定个人身份。测试时容易被误认作价格字段的姓氏 Price 已从候选列表排除。电话使用 `415-555-0100` 至 `415-555-0199` 这一虚构、不可接通号码段，见 [NANPA 说明](https://www.nanpa.com/numbering/555-line-numbers)。部分网站可能拒绝这类测试号码。插件会取消勾选新闻或促销邮件的订阅框。

遇到电话区号下拉框时，插件会尝试先切换到美国 `+1`，再填写美国格式电话号码。已适配 Vivigirl 使用的 Shopyy 区号控件；如果能识别出非美国区号却无法切换，插件会跳过电话并提示手动处理。填写文本时会让输入框实际获得焦点并失焦，以触发页面的浮动标签和校验状态更新。

## 测试卡

点击“生成资料”后，如果页面显示信用卡输入框，插件会填写测试卡号、有效期、安全码，并把 Cardholder name 填成同一组收货姓名。若信用卡输入框稍后才出现，插件会自动补填空字段。默认选中 `4242 4242 4242 4242`，另预置 `5555 5555 5555 4444` 和标注 **3DS** 的 `4000 0027 6000 3184`；三张均列于 [Stripe 官方测试卡文档](https://docs.stripe.com/testing#regulatory-cards)。3DS 卡在 Stripe 测试结账中要求身份验证；实际验证界面由网站的支付集成触发，插件只填表，不提交付款。安全码默认 `234`，有效期取浏览器当前月份往后推 2 年（例如 2026 年 11 月生成 `11/28`）。在配置中可新增其他支付服务的官方测试卡号、删除、上移、下移或按卡号排序；选中的卡号作为填充默认卡。插件的姓名、地址等表单填充不限定 Stripe。预置卡号只用于 Stripe 测试环境；其他支付服务请使用其官方测试卡和测试环境。请勿将真实银行卡号保存在插件配置中。

## 已知限制

- 首版只覆盖常见原生输入框、`select` 和部分自定义下拉菜单。实际 checkout 若把字段放在跨域 iframe、封闭 Shadow DOM 中，或使用特别的控件，需要按页面结构适配。
- 已尝试在结账页内的支付 iframe 中补填空卡片字段。支付服务若阻止扩展注入、使用封闭 Shadow DOM 或不接受程序触发的输入事件，仍可能无法填写，需要按实际页面适配。
- 选择州时会优先查找包含目标州选项的下拉框，并等待国家切换后选项出现。
- 为在任意域名的匹配路径上显示按钮，Chrome 会提示较宽的网站访问权限。插件本身不向外发送表单数据。
- 本插件只适合隔离的测试订单流程，避免把这些地址用于实际发货。
